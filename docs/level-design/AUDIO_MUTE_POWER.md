# 静音播放省电

仅实现用户选定的第1项：音量0时停止硬件播放。地图、数值、界面、自动调光、CPU电源管理和无线配置不改。

音频任务是编解码器和曲目状态的唯一拥有者。进入静音时用一块10ms缓冲将最后采样平滑降到0，再写入8块静音，覆盖固定BSP的6个240帧DMA描述符；随后调用官方输出静音和关闭接口。ES8311关闭路径控制功放并暂停DAC，数据接口关闭播放TX。BSP已启用的独立RX通道不在本次范围，不能宣称所有I2S时钟或整机都已休眠。

关闭后任务等待通知，不再定期写零PCM或合成音频。重复设置相同音量/曲目不通知。任务句柄一旦公布便保持到应用重启，包括硬件错误期间，避免跨核通知已删除任务。初始音量0时不初始化音频硬件。

静音期间通过单调时钟记录经过时间，只在控制变化唤醒时补进曲目进度。新接口只允许在静音状态推进，不生成PCM，且跳过重复完整循环，24小时等待仍有固定上界。静音中换层会切到最新曲目。恢复时先保持硬件静音并预填零数据，再复查最新音量、解除硬件静音并用原合成器的增益斜坡淡入。已有codec的打开/关闭/写入失败最多每秒重试，避免滑杆通知导致重试风暴。首次BSP初始化或codec工厂失败后则停用音频直到重启：固定BSP的部分失败路径未完整回滚，不能反复调用工厂泄漏堆或总线设备。任务仍保持有效通知句柄。

验证使用真实game_audio.c任务和game_music.c，仅替换RTOS、时钟、BSP/codec接口，覆盖正负采样淡出、反复静音恢复、初始静音、静音中切曲与初始化/打开/音量/静音/解除静音/关闭/播放失败。静音长等待期间断言无PCM写入且输出已关闭。所有10曲另有连续静音与阻塞后补时的PCM一致性、24小时补时检查。主机验证不能确认实测电流和扬声器是否有爆音。
