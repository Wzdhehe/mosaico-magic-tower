# 怎么让这个游戏更好玩

> 本文的所有结论都来自本仓库的真实数据：`main/tower.c` 的地图、`tests/win_route.json`
> 的实际通关路线、以及链接真实 `tower.c` 跑出来的探针结果。
> 玩法侧的参照基准是开源引擎 `ckcz123/mota-js` 与真实成品塔 `arcxingye/MagicTower`
> （胖老鼠 24 层）；布局规范见同目录的 `magic-tower-map-design-skill.md`。

---

## 0. 一句话诊断

**这个游戏 97% 的内容是走路，而且走路不会输。**

战斗只占全局的 3.0%，而每一次战斗都**在开打之前就被判定为"必胜"**——
`main/tower.c` 的 `tower_move()` 会先算一遍伤害，`winnable == false` 就直接返回
`TOWER_STATUS_TOO_STRONG`，连打都不让打。玩家永远不会输，也永远不会被追着跑。

与此同时，**数值其实调得很紧**——只是这个紧度被完全浪费了（见 §2）。

## 1. 现状实测

| 指标 | 实测值 | 来源 |
|---|---|---|
| 全局回合数 | **568**（612 个动作） | `tests/win_route.json` |
| 战斗次数 | **17** | `tests/win_route.json` |
| 战斗占回合比例 | **3.0%** | 17 / 568 |
| 每层战斗数 | 3, 2, 1, **0**, 2, 2, 2, 1, 2, 2 | `enemy_encounters` |
| 全塔怪物总数 | 20（第 4 层 **0 只**） | `main/tower.c` |
| 死亡条件 | **不存在** | `tower_move()` 的 TOO_STRONG 门禁 |
| 地图伤害（陷阱） | **不存在** | 地图里没有危险地形 |
| 回合上限 | 无（`MAX_TURNS` 只是防溢出） | `tower.c` |
| HP 上限 | **无**（药水可无限叠加） | `tower.c` |
| 商店购买次数（最优路线） | **1 次** | 479 / 494 金币未花 |
| 目标 | 1 个（公主） | `tower.c` |

### 1.1 为什么"永远不死"是最大的问题

```c
/* main/tower.c, tower_move() */
if (is_enemy(tile)) {
    tower_enemy_preview(h, tile, &preview);
    if (!preview.winnable) return set_status(h, TOWER_STATUS_TOO_STRONG);
    ...
}
```

`preview.winnable` 的定义是 `damage < hp`。所以：

- 只要这场仗打得赢，**一定打得赢**（战斗是确定性的回合公式）；
- 只要打得赢，**游戏不让你打**——因为它会先告诉你"太強了"。

于是战斗退化成一个**纯粹的过路费**：付 HP，走过去。没有任何决策含量。

> 这不是"太简单"，这是**没有游戏**。经典魔塔之所以紧张，不是因为战斗难，
> 而是因为**你可能输，而且输了要付代价**。

### 1.2 数值其实调得很紧——只是被浪费了

最优路线的数据：

```
total HP damage taken : 1185
final HP              : 75
=> 全程可支配 HP 总量 : 1260
```

而全塔血瓶是 12 小（+30）+ 10 大（+80）= 1160，加初始 100 = **1260**。

**也就是说：最优路线必须喝光全部 22 瓶药，一滴不剩，最后只剩 75 点血——
血量预算的余量只有 6.0%。**

这个经济调得非常好。**但因为没有死亡条件，这 6% 的余量永远不会被兑现**：
余量不足时游戏只是把你挡在门外，提示"太強了：先收集宝石"，
玩家回头捡两颗宝石再来，然后继续。紧张感完全没有传导出来。

### 1.3 商店经济 97% 是死的

全塔敌人总金币 494（`enemy_gold()` 求和）。最优路线花了 **15 金币**（1 次购买），
剩下 **479 金币**躺在口袋里。10 层楼 1 个商店，等于没有商店。

## 2. 改什么：一个最小的"变好玩"改动集

按**投入产出比**排序。前四项做完，这个游戏的手感就会完全不同。

### G1 ★★★★★ 给战斗装上"真的会死"

**问题**：见 §1.1。

**改法**（`main/tower.c`）：

```diff
     if (is_enemy(tile)) {
         tower_enemy_preview(h, tile, &preview);
-        if (!preview.winnable) return set_status(h, TOWER_STATUS_TOO_STRONG);
         h->state.phase = TOWER_PHASE_COMBAT;
         h->state.pending_x = (unsigned)x; h->state.pending_y = (unsigned)y;
         h->state.pending = preview;
         return set_status(h, TOWER_STATUS_CONFIRM);
     }
```

并在 `tower_confirm()` 里：

```c
 h->state.hp -= h->state.pending.damage;
+if (h->state.hp == 0) {
+    h->state.status = TOWER_STATUS_DEAD;   /* 新增状态 */
+    h->state.cleared = false;
+    /* 保留已拾取的道具与已开的门：回到本层入口重来，不是从头 */
+    return set_status(h, TOWER_STATUS_DEAD);
+}
```

**关键设计选择**：死亡**不要从头开始**。经典魔塔死亡回本层是"硬核"的，
但掌机上的 10 层塔（568 步）从头再来一次会劝退所有人。
**推荐：死亡后回到本层楼梯口，保留钥匙/宝石/已开的门，只回滚 HP。**
（现代 roguelite 的做法，也是 `mota-js` 之外多数复刻的做法。）

**这一条会同时激活 §1.2 里那 6% 的血量余量**——整个数值系统瞬间有了意义。

> **配套**：弹窗要明确显示"这一战会扣 N 血，你现在有 M 血"。M < N 时按钮应该
> 变成"送死"而不是"战斗"，并且给出确认。

### G2 ★★★★★ 给 HP 加上限

**问题**：HP 无上限，22 瓶药把 100 血堆到 1260 血，"血"从来不是资源。

**改法**：

- `tower_snapshot_t` 增加 `uint32_t hp_max;`
- 上限只由**特定道具**提升（例如"红心水晶：HP 上限 +30"），药水只是**回复**，
  回复不超过上限。
- 上限公式建议：`hp_max = 100 + 10 * (floor+1) + 30 * 生命水晶数`
  → 10 层约 200~230。22 瓶药（约 1160 点回复）远超这个池子，
  于是**"药要留给硬仗"**自然成为策略。

**收益**：药水从"捡了就用"变成"存着"，地图上的血瓶位置开始有决策价值。
这正是参考塔里"血瓶看着放，在区域开头/强怪后面多放"那条经验的来源。

### G3 ★★★★☆ 红钥匙必须稀缺（`红钥匙 < 红门`）

**问题**：本仓库 **4 把红钥匙 / 4 扇红门**，一条不多一条不少。
没有任何一层会"欠账"，玩家永远不需要回头。

**参照**：胖老鼠 24 层实测 **红钥匙 9 < 红门 13**（比值 0.69）。
论坛原话：

> **总钥匙数一般大于必开门数小于总门数。**（必开门 = 拿到全部宝石所必须开的门）

**改法**：把红钥匙减到 **3 把**、红门保持 5 扇（或钥匙 3 / 门 5）。
然后把其中一把红钥匙放到**必须绕回去拿**的地方——
比如放在第 2 层的一个"需要第 6 层才能打"的怪后面。

**收益**：这是整个魔塔最核心的机制。玩家会开始记"我欠一把红钥匙"，
会在第 7 层专门规划一次下潜。**一个数字的改动，引入整个"回头"文化。**

### G4 ★★★★☆ 引入"绕怪门"（咸鱼门）

**问题**：现在每扇门都是硬性钥匙墙，每场战斗都是免费过路费。玩家没有取舍。

**改法**：给部分门加一个**等价收益的第二条路**。经典写法：

- 门后面是宝物，**打怪**（掉 HP）或**用钥匙开门**（花钥匙）都能拿到；
- 于是玩家在门前做真正的权衡：我的 HP 紧张吗？这把钥匙后面还有用吗？

论坛原话：

> 一般是不花钥匙打怪，花钥匙可以绕怪；或者黄门要打怪，蓝门直接拿道具

**注意**：这与 G3 是一对。G3 让钥匙变稀缺，G4 让钥匙有第二种用法，
两者共同把"钥匙"从通行费变成**可交易的资源**。

### G5 ★★★☆☆ 地图上加危险地形（血网 / 岩浆）

**问题**：当前地图里没有任何"走一步就掉血"的东西，
**所以路径长度完全不重要**——绕远路不花任何代价，走直线永远最优。

**改法**：加一种地形，每步扣固定血量（参考塔的"血网 lavaDamage = 100 / 步"）。
放在两个"要绕远路"的区域之间。

**收益**：路径长度第一次成为成本，地图的形状开始有意义——
这正是"为什么要这样设计这层楼"能变成一个问题的原因。

> 论坛的反面警告也要遵守：
> 「如果塔里的地图伤害普遍远小于怪物伤害，那么基本上可以认为这个地图伤害是可以删除的。
> 地图上全是数字，玩起来就会很难受」——血网伤害要**明显**大于普通怪的一击，
> 但不能大到让玩家绕路时必死。

### G6 ★★★☆☆ 给每层一个次级目标

**问题**：10 层只有 1 个目标（公主），8 层是纯走路。

**改法**（成本很低，收益很高）：

- 每层放 1 个**宝箱**，需要打掉特定怪才能开（引擎里就是 `afterBattle: openDoor`）；
- 或者每层统计"本层拿到几把钥匙"，进层时显示目标；
- 或者给每层一个**收集品**（如"第 3 层的骑士徽章"），集齐给奖励。

**收益**：每层都有"这一层我要拿什么"，10 层不再是 8 个前奏 + 2 个高潮。

### G7 ★★★☆☆ 商店定价阶梯 + 钥匙商人

**问题**：商店 15 金币换 +3 攻/防，1:1，没有梯度；金币 97% 花不出去。

**改法**（直接抄参考塔的定价，它是被验证过的经济学）：

| 商店 | 定价 |
|---|---|
| 黄钥匙 | **10** 金币 |
| 蓝钥匙 | **50** 金币 |
| 红钥匙 | **100** 金币 |
| 1 级商店 | 25 金币 → 攻+4 / 防+4 |
| 2 级商店 | 100 金币 → 攻+20 / 防+20 |

钥匙 **10 : 50 : 100 = 1 : 5 : 10** 的价格阶梯直接定义了"红钥匙最稀缺"。

> 论坛：**「不建议放蓝钥匙」（在黄门后面）——由于这个塔蓝钥匙价值高于黄钥匙，
> 因此换蓝钥匙尽量用多个黄钥匙，或者需要打怪。**（即：高级钥匙应该锁在需要战斗的后面。）

**收益**：金币有了去处；红钥匙从"捡到就赢"变成"要花 100 金币 + 绕远路去拿"。

### G8 ★★☆☆☆ 加计分与步数

`state.turns` 已经在记了，只是没显示。加一个"本次 568 步 / 通关用时"，
再给个评级（按步数和剩余血量算 S/A/B）。
参考塔有 50+ 个榜单，这是最便宜的长期可玩性。

### G9 ★★☆☆☆ 隐藏层 / 岔路

10 层塔可以做一次"三分支"：第 8 层拆成左/右两个子层（`canFlyTo: false`），
玩家必须选一边走，且状态栏都显示"8F"——**玩家不知道自己在哪个分支**。
这是胖老鼠 24 层 MT22 的结构（三个同名子层），也是它最出彩的设计之一。

### G10 ★★☆☆☆ 敌人特技

当前敌人只有 hp/atk/def 三个数，**每个怪都是纯粹的 HP 税**。
参考塔有领域 / 破甲 / 反击，让不同怪对不同 build 有不同价值。

一个最小实现：给"石魔"加**破甲**（无视玩家 30% 防御）。
这会让"堆防御"不再是万能解，玩家必须考虑攻防配比——
也顺便解决"所有怪都该打，没得选"的问题。

## 4. 实施路线图

### 第一阶段：机制（不改地图就能生效）

| 步骤 | 改动 | 触及文件 | 风险 |
|---|---|---|---|
| 1 | 允许失败 + 死亡回本层 | `main/tower.c`、`main/game_view.c` | 中：新增 `TOWER_STATUS_DEAD`，要补 UI 与存档校验 |
| 2 | HP 上限 | `main/tower.c`（`tower.h` 加字段）+ 存档格式 | **高**：存档格式变了，`SAVE_VERSION` 要从 3 升到 4，`tower_import` 的语义校验要同步 |
| 3 | 战斗弹窗显示"当前 HP / 战后 HP" | `main/game_view.c` | 低 |
| 4 | 步数与评级显示 | `main/game_view.c` | 低 |

> **第 2 步会影响存档兼容性**。`tower_export`/`tower_import` 是固定 2048 字节的
> 手工序列化格式（`SAVE_VERSION 3`），加字段必须同时：
> 升版本号、更新 `encode`/`decode` 的字段顺序、更新 `valid_state()` 的
> 一致性校验、并让旧存档**明确失败**（而不是被误判为合法）。
> 这条是本 PR 里 `tools/render_probe/verify_model_defects.c` 想守住的那类边界。

### 第二阶段：地图（新十层）

1. 先用 `tools/analyze_maps.py` 跑现有十层，拿到基线；
2. 按 `magic-tower-map-design-skill.md` §7 的 18 条校验逐条改；
3. 每改一版，跑 `tools/magic_tower_route.py` 重新生成 `tests/win_route.json`
   （README 明确要求："regenerate `tests/win_route.json`/`win_route.h` after every map change"）；
4. 目标：**新最优路线的血量余量从 6% 变成 2–4%**（更紧，但仍有安全垫），
   且**至少一次"必须回头"的资源断点**。

### 第三阶段：内容扩展

钥匙商人、分支层、敌人特技、计分榜。

## 6. 顺带修掉的两个真 bug

`tools/render_probe/verify_model_defects.c`（本 PR 新增）在链接真实 `tower.c` 后跑出的结果：

### 6.1 哨兵（Sentinel）会**永久损坏存档**

```
preview(SENTINEL)      : hp=999 atk=200 def=120 gold=0
-> the game pays 0 gold; valid_state() assumes 60
!! MISMATCH: validator's enemy_gold(SENTINEL)=60 != preview gold=0
import(save with sentinel killed, gold=0) -> TOWER_ERR_SAVE (save is unloadable)
!! CONFIRMED: killing the sentinel corrupts the save permanently
import(save with sentinel killed, gold=60) -> TOWER_ERR_SAVE (still rejected)
import(control, untouched save)          -> OK
```

三个原因叠在一起：

1. `tower_enemy_preview()` 的 `default:` 分支给哨兵发 **0 金币**；
2. `valid_state()` 用 `enemy_gold(TOWER_TILE_SENTINEL)` = **60** 去重构金币；
3. `valid_state()` 还有一条显式的 `consumed[TOWER_TILE_SENTINEL]` → 直接判非法。

**结果：只要杀了哨兵并存档，这个存档就再也读不出来了**（游戏会提示"存档已损坏"）。

而哨兵**是能打的**：全塔金币 494 ÷ 15 = 32 次购买，
最大可达 `攻 = 12 + 5×13 + 3×32 = 173 > 120`（哨兵防御）。
也就是说，玩家只要把全塔金币全部换成攻击、然后回头打掉第 1 层那个
`(3,9)` 的哨兵，存档就废了。

**修法建议**（二选一）：

- **A**：哨兵不该是敌人。把 `X` 从 `is_enemy()` 的范围里拿掉，改成一种"不可破坏的墙"
  （或一种需要特殊道具才能破的机关）。它现在的数值（hp 999 / atk 200 / def 120）
  本来就不是给玩家打的。
- **B**：把它做成真敌人，并**同时**修三处：`tower_enemy_preview` 的 default 分支
  补上哨兵数值（hp/atk/def/gold 与 `enemy_gold()` 一致）、
  删掉 `valid_state()` 里的 `consumed[TOWER_TILE_SENTINEL]` 显式拒绝、
  并检查 `TOWER_STATUS_TOO_STRONG` 不会把它变成一堵永远打不开的墙。

**推荐 A**：一个"永远打不过但看起来能打"的怪，是最坏的玩家体验。

### 6.2 游戏没有失败条件，但**有软锁**

因为 `TOO_STRONG` 会把打不赢的战斗挡在门外，而 HP 又**没有上限**、
药水可以无限喝、地图上没有陷阱——所以玩家永远不会死。

但反过来：**如果玩家在错误的顺序下把 HP 耗光，又恰好把药水喝完了，
他会卡在"打不过也死不了"的状态。**全塔 HP 预算只有 1260 而最优路线就要花 1185，
余量 6%——顺序稍有偏差就可能撞上这个死结，而且游戏**不提供任何提示**。

这正好说明 §2 的 G1（允许失败 + 死亡回本层）和 G2（HP 上限）不是可有可无的润色，
而是**修 bug**：有了死亡回本层的兜底，玩家永远不会真的被锁死。
